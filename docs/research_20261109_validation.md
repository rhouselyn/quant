# 研究验证与数据时序审计：2026-11-09

本文件只记录仓库阅读、原始论文检索和小规模只读核验，不训练、不改 `src/`、不覆盖 baseline、配置、预测或历史报告。研究对象是当前 ak2000、30 特征、580 股 canonical baseline，冻结模型参考为 `merge_abl2000_base_3seed`；较早的 yahoo/2004、fin2、live vintage 不能不加说明地混为同一基准。定位依据：`docs/baseline_monopen.md:7`、`configs/hierarchical_580_monopen_baseline.yaml:62`。以下“确认”指代码或本次读取可直接证明；“待核验”不等于已经发现收益虚增。

## 1. 结论及证据等级

当前最需要投入的是验证与会计的一致性，而不是增加新的显著性门槛。已有流程包含训练期预留、验证选 epoch、跨 seed 融合、成本和配对分析；但还存在以下具体缺口：

| 等级 | 发现 | 对研究结论的影响 |
| --- | --- | --- |
| 确认 | 当前股票池和行业是当前快照回溯；早期实际有观测的股票显著少于580 | 能说明这个 survivor universe 的历史表现，不能直接推广为当时全 A 股的可交易表现 |
| 确认 | baseline 五周训练预留覆盖当前一周 open-open 标签及五周对比目标 | 不应把当前训练边界误报为已发现标签泄漏；新 horizon 需要重新算边界 |
| 确认 | 最后一个 validation 锚点的退出价格晚于第一个 test 打分时点 | 验证选轮仍有边界污染；purge 不能只做在训练端 |
| 确认 | 离线 epoch 融合丢失 `tradable`，live 三 epoch 递归平均不是等权 | 选轮、离线评估、线上评分并非完全相同的数据契约和算术 |
| 确认 | test 已被多次用于研究对比、基线切换及执行参数研究 | 新研究应把它标为“历史探索/回放”，不能继续称一次性独立确认 |
| 确认 | 当前三腿组合回报是两个腿净收益的50/50算术混合；短腿已修复 log/simple 与漂移问题 | 修复后的历史数值优于修复前的可信度，但仍不等同完整可融资、可借券现金账户 |
| 待核验 | 复权历史版本、财报重述、真实退市与券源、停牌退出、缺周的真实持仓路径 | 当前资料不足以量化它们各自造成多少偏差，不能给出“已全部无泄漏”的保证 |

## 2. 数据、样本和特征的时间边界

### 2.1 580股×1399周不是811420个独立样本

只读核验 `data/sw_580_observed_features_2000_fri_path30/weekly.parquet` 得到811420行、580个股票、1399个周五锚点，区间2000-01-07至2026-10-23。`observed` 的每周股数中位数为：

| 年份 | 2000 | 2004 | 2010 | 2017 | 2021 | 2026 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 当周 observed 股数中位数 | 175 | 252 | 371 | 562 | 580 | 580 |

这些数字还没有扣除特征暖机、40周覆盖门、标签缺失和入场条件，因此也不是最终训练可用股数。`hierarchy_data.py:119` 至 `:122` 用当期特征完整性及过去覆盖门得到 available；`hierarchy_engine.py:405` 又要求当期至少10个可用标签。每个训练样本实质是“某周的整个截面及其历史窗口”；同周股票共享市场和行业冲击，相邻40周输入大量重叠，五周对比目标也相关。增加股票可以增加横截面信息，不能把时间上的证据量乘580。评估收益以周度组合序列为核心；推断时保留整周截面及时间块，不独立抽股票行。

`configs/hierarchical_580_monopen_baseline.yaml:96` 明示 `current snapshot, retrospective`；`docs/baseline_monopen.md:56` 明示29行业各20股。`prepare_hierarchy_580.py:55` 也承认 survivor sample。行业历史变迁和已经退市的证券并未由这一固定名单重建。必须把“历史时点股票池”列为独立数据工程任务；换成更大的当前股票池并不会自动消除幸存者偏差。

若需要近似有效时间样本量，可作为诊断报告 `T_eff ≈ T / (1 + 2 Σ rho_k)`，但该式依赖平稳性和截断选择，不应打印成精确独立样本数。年级别分组也只有约六段且相关，不能把“赢4/6年”解释为四次独立试验。

### 2.2 已有特征防护有效，但适用范围要说清楚

`data.py:284` 至 `:323` 的价格量额特征以当前及过去的差分/rolling计算；负向 shift 只出现在单独的 target 列。`hierarchy_data.py:10` 至 `:15` 先在已观测bar上计算特征，然后仅向前携带；市场特征在 `:18` 至 `:32` 使用当期及过去截面。`arrays` 的全局均值方差仅 fit `raw[:train_end]`，逐周横截面标准化使用同一时点的可观测股票（`:123` 至 `:135`）。这些操作本身没有显示未来bar进入当前特征。

但“标准化按周横截面做”只能证明这个运算局部没有跨期引用，不能证明股票池、原始数据版本、模型参数或选轮规则没有使用后来信息。`live_score.py:10` 至 `:14` 和 `:160` 的“none”说明应按这个局部范围理解。

可选 daily 分支的 global fit 截止使用 `weekly_dates[train_end]` 的 `side='right'`，包含第一验证周的日数据（`hierarchy_data.py:72`）。这是可选分支的边界风险，当前canonical没有 `daily_path`，不能归责于当前30特征主线。新增 daily 实验前应单独修订并做截断不变性检查。

### 2.3 复权和财报只能做有条件的判断

当前配置实际读取缓存；`provider: yahoo` 等陈旧元数据不能覆盖实际来源事实。基线文档声明 akshare hfq、量额raw（`docs/baseline_monopen.md:54`），`build_raw_ak2000.py:26` 至 `:38` 读取 hfq OHLC并拼接未复权量额。后复权与相对价格特征减少了某些前复权历史重写问题，但仍需核验公司行动日期、分红口径、原始/复权价一致性及数据供应商的历史修订。仓库没有本次可证明的完整 as-of vintage 档案；不能从“hfq”三个字推出严格 point-in-time。除权日涨跌停可成交性应以未复权成交价和交易所参考价检查，不能仅靠复权价比值推定。

财报扩展使用 `report_date + LAG` 后 `merge_asof(... direction='backward')`，分母为未复权股价，填充中位数来自训练段（`add_fin_features.py:27`、`:49` 至 `:80`）。这优于直接按报告期入表，但法定披露滞后代理并不能覆盖延期披露、事后重述、公告后才可见的供应商版本；同一报告保留最后一条也需要版本审计。当前baseline的30个 `feature_names` 不包含fin列，故这些风险主要约束未来财务臂，不是当前主模型已使用财务未来信息的证据。

## 3. 标签、purging、选轮和线上线下的一致性

### 3.1 应按“标签结束时刻”，而不是仅按signal_date切分

`hierarchy_data.py:140` 至 `:159`：周五 t 特征，下一周首个交易日开盘买入，再下一周首个交易日开盘卖出；开盘缺失或跌停时，退出回退到退出周收盘。标签因此涉及 t+1 和 t+2 的价格，且少数标签结束更晚。它是监督目标中的未来信息，属于合法标签；当标签的结束晚于训练/选轮实际截止时，就会变成不合法的信息使用。

当前训练 `reserve=max(temporal_horizon, common_training_horizon)=5`，训练索引严格小于 `939-5`（`hierarchy_engine.py:403` 至 `:406`；配置`:76`、`:114`）。五周对比学习目标的最晚使用点仍在训练段，当前open-open标签也被覆盖。因此，**当前训练端的这一检查通过**。该reserve没有显式纳入所有潜在 `target_horizon`，未来更长标签或异常退出延迟不能照搬通过结论。

验证选轮却调用 `predict(train_end, valid_end)`，随后直接按这一段净Sharpe argmax（`hierarchy_engine.py:533`、`:550`、`:579`）。本次读取日历确认：

| 索引 | signal_date | 角色 |
| --- | --- | --- |
| 939 | 2018-01-05 | validation起点 |
| 1094 | 2020-12-25 | 倒数第二个validation锚点 |
| 1095 | 2021-01-01 | 最后validation锚点 |
| 1096 | 2021-01-08 | 首个test打分锚点 |
| 1097 | 2021-01-15 | 最后validation标签的退出价格所在周 |

最后validation锚点有579个股票的下一周、再下一周开盘非缺失。其正常退出在2021-01-11，晚于首个test的2021-01-08收盘评分；异常回退还可能到2021-01-15收盘。这是具体的选轮边界污染。不能据此断言全部历史优势由这一周造成，影响大小需要后来在隔离产物中重算。

拟议执行规则：每个样本记录 `feature_asof`、`entry_at`、`label_end_at`、`decision_at`，只允许所有用于拟合、预处理选择和epoch选择的标签满足 `label_end_at <= frozen_selection_at`。滚动每折重新检查。当前实现可以先采取保守周数裁尾作为过渡，但正式规则应依据真实交易时间，避免节假日/停牌回退后失效。Purging移除跨边界的目标区间；embargo用于额外防止特定重叠或训练位于评估之后的依赖，不应把40周历史输入机械等同40周必须丢弃。只用过去训练的walk-forward可以合法读取过去历史输入，关键是拟合与标签截至时刻。[López de Prado的原著目录（第7章purging/embargo）](https://www.wiley.com/en-ca/advances-in-financial-machine-learning-p-9781119482086)、[Hudson & Thames原始实现接口](https://github.com/hudson-and-thames/mlfinlab/blob/master/mlfinlab/cross_validation/cross_validation.py)。

### 3.2 epoch选择本身不是罪名，必须比较同一个完整算法

当前选轮以验证Top-20净Sharpe；离线 `pick_epochs` 和 `build_ens` 从验证指标选成员并对各epoch截面z分数取等权均值（`ensemble_best_window.py:52` 至 `:69`）。只要选轮窗口、指标、边界规则与成员数提前冻结，候选和baseline自然选出不同epoch是完整训练算法的内生结果，不能仅因成员不同就称“混淆导致无效”。固定epoch窗口比较只适合解释机制，并应事前指定；不得在看到结果后挑一个对任一方有利的窗口作最终判决。

`window`在best=1时仅有两个成员，`window3`固定为三个；live使用后者，而部分历史离线使用前者（`ensemble_best_window.py:35` 至 `:49`；`live_score.py:34` 至 `:48`）。协议必须报告实际成员数，而不是把目录名 `_ens3` 当作事实。历史baseline保留原版本；后续对照同时跑相同新规则，单列规则变更的影响。

更具体的一致性问题已确认：

1. `live_score.py:124` 至 `:128` 依次 `(merged + next)/2`，三成员实际权重为1/4、1/4、1/2；离线 `build_ens` 的均值是1/3、1/3、1/3。纯数值assert已验证；最终z-score无法一般地抵消不同成员权重。尚未本次重跑所有live模型，故不报告实盘股票变化或损益量。
2. `ensemble_best_window.py:66` 至 `:69` 不输出 `tradable`。实际 `outputs/merge_abl2000_base_3seed/predictions.parquet` 仅有date/symbol/score/realized_return/rank_ic五列；原epoch预测带这一字段。`long_only_backtest`仅在存在该字段且未传入groups时过滤（`long_only.py:54` 至 `:57`）。因此同样标注monday-open不保证同样执行了入场过滤；`groups`捷径也需审计。离线/线上/验证书的字段和每期候选必须逐值对齐后才可宣称完全复现。
3. `reselect_epochs.py:1` 至 `:9` 明确把原来留作sanity test的窗口纳入live选择。这可以用于之后的真实前瞻部署，但被纳入的数据从此属于选择数据，不得再用来认证该live方案。

`save_epoch_scores`每epoch会计算test预测（`hierarchy_engine.py:534` 至 `:540`），但没有反传，也没有在该函数内用test指标选best；**不能把存盘等同直接训练泄漏**。它增加了研究者随时浏览并据此改方案的机会，因此“不读test”需要文件访问/评估协议，而不只是 `defer_test=True`。

### 3.3 现有walk-forward可复用思想，不能原样当新证据

`walkforward_monopen.py:151` 至 `:158` 每年训练至Y-2、用Y-1选轮；这是可复用的滚动结构，但继承上述验证标签裁尾问题。更直接的是 `:55` 读当前canonical配置，而 `:60` 的参考仍是旧 `merge_monopen_attnenc_d128h4_3seed`。复用前必须核对数据源、基线指针、历史fold产物、执行与成员规则，不能只改文件名。`run_fold`有删除不完整产物/旧ensemble逻辑（`:168`、`:182`）；本研究没有运行它。

## 4. 交易会计：纯多、纯空、组合必须各自可解释

`long_only.py:61` 将log标签转换为简单收益；`:66` 至 `:74` 用漂移后的旧权重计算买卖名义额、计成本、再算净收益。`skipfill_short.py:74` 至 `:104` 已于11月8日修复简单收益、空头名义额漂移和再平衡换手，这是应保留的修复。不要引用修复前纯空年化数字作为比较对象。

仍需明确：下一周实际开盘可成交性属于执行时点条件，不是周五可提前知道的模型输入。历史撮合可在开盘判断是否成交，但“剔除涨停并瞬时补到第20名，且所有替补仍在同一个已知开盘成交”需要真实订单机制支持，不能只因使用 `tradable` 就保证可执行。缺开盘/跌停卖不掉却按该周收盘退出是研究代理；延期到周五后，与下一周一新开仓并存时必须保留占用资本。缺失收益记平可以披露，不能取代退市和长期停牌的损失处理。ST 5%板未建模，源代码已说明（`hierarchy_data.py:96` 至 `:104`）。

空头季度“可融资融券名单”也不等于当天券商可借券。当前 `skipfill_short.py:41` 至 `:60` 使用季度文件的 `rz` 字段；应追溯其来源、有效起始日、融资/融券字段含义与当日实际库存。它没有证明“每只均可在历史时点借到”。`build_baseline_stack.py:54` 至 `:56` 已披露未计借券费及真实券源待确认。

组合 `r_combo=(r_long+r_short)/2`（`build_baseline_stack.py:65` 至 `:67`）对应每期恢复50/50腿资本的简化定义；若展示的是全账户净值，需对腿间再分配、现金、保证金和抵押品、空头卖出所得、分红补偿、借券费、融资利息、拒单/召回及追加保证金给出同一现金账本。目标权重差不等于实际成交，必须先执行可行订单，再计算持仓损益。自融资和交易/持有成本的基本参考为[Boyd等《Multi-Period Trading via Convex Optimization》，第2章](https://web.stanford.edu/~boyd/papers/pdf/cvx_portfolio.pdf)；这里是采用其会计原则，不主张本项目因此需要加入优化器。

**最低会计核验清单（后续实施，不在本次运行）**：单股涨跌、部分成交、现金空仓、空头上涨导致保证金占用上升、相同持仓但权重漂移、卖出延迟跨周、借券召回、费用为零/翻倍、手数舍入。预期结果要手算，不能仅由另一份相同公式脚本证明自己。

日历亦影响指标。本次主研究并行检查发现冻结组合表仅283个收益行，逐年为52/46/46/49/52/38行；`long_only.py:30`、`:31`仍按52期年化，`build_baseline_stack.py:65`先取交集丢缺失。该数字既不是302个test锚点，也不自动等于完整自然时间现金曲线。必须保存完整交易日历，解释每个缺期是否休市、无新仓、保持持仓、价格缺失或标签尚未成熟；不能简单填0。原历史读数原样归档，另列完成日历与真实持仓核验后的新口径。在弄清缺口前，按elapsed天数直接换年化仅是敏感性演示，不是真实修正值。

## 5. 历史test暴露、统计工具与结论措辞

### 5.1 已选择过的数据不能通过重分折恢复独立性

基线文档用2×2历史对比决定从fin2切回base30（`docs/baseline_monopen.md:15` 至 `:37`）；台账持续记录test中的融合、持仓宽度、平滑、对冲和空头规则（如 `experiment_ledger.md:1354`、`:1678`、`:1759`）。11月9日报告明确在同一批窗口做190次检验（`overnight_20261109_report.md:13`）。因此2021–2026应当列为“反复暴露的历史探索集”。

2016–2020即使在某个重新训练的vintage中未用于那个模型的调参，也不意味着整个研究过程从未见过：它与当前训练/验证时期及既往设计选择交叠。称其“另一个时代的回放”合理；称全研究层面的“从未碰过的独立年代”需要完整访问与决策历史，目前不能证明。

Nested/prequential协议可以约束今后“内部选参→外部评价”的流程，并减少算法运行时的泄漏；但研究者已经根据这些年代选择了股票池、特征、损失、持仓和候选家族，事后再分折不能擦除这些决定。把整套选择程序在历史外折重跑有诊断价值，标签应为“事后历史回放”。强度更高的确认需要规则冻结之后自然到来的新数据，或能够证明未参与任何设计选择的外部数据。单纯“换一个seed”“换一个年代命名”“套一层nested”均不构成新独立信息。模型选择本身也会过拟合的原始证据见[Cawley与Talbot，JMLR 2010](https://jmlr.org/papers/v11/cawley10a.html)。

### 5.2 已有harness保留为诊断，不能一键认证alpha

`validation_harness.py` 已提供DSR、CSCV/PBO、4/8/13周圆形块bootstrap，优于只报一个Sharpe。但其当前边界为：

| 实现 | 能回答什么 | 不能回答什么 |
| --- | --- | --- |
| `:154` 至 `:163`：DSR按输入臂数及固定20次重算 | 在这些试验数量/Sharpe分散度假设下的敏感性 | 仓库全部人工和程序搜索的真实选择偏差；6/20不是历史试验总量 |
| `:80` 至 `:101`：16块CSCV | 当前这组现成策略在块重排中的选优不稳定性 | 时间有序部署表现；完整训练与选参流程的全局过拟合概率 |
| `:104` 至 `:124`：5%/95%百分位 | 单曲线相对基准超额的90%描述性区间 | candidate减baseline的增量区间、95%区间或经过零假设校准的检验p值 |
| `:161`：普通均值t | 描述效应相对朴素标准误的大小 | 自相关稳健结论、选择后错误率保证 |

尤其 `p_mean_le0` 是未中心化bootstrap均值落在零以下的比例，不应改名成已校准的频率学p值。候选与baseline高度相关时，必须对同周差或联合向量做配对抽样；分别bootstrap后对比两条区间会丢失配对信息。[Bailey与López de Prado的DSR原文](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)强调试验选择、非正态与样本长度；[Bailey等的PBO原文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)给出对策略选择过拟合的框架。两者均不应被解释为交易可执行性或因果alpha的证明。

11月9日报告对本轮190格做max统计量校正，比只计6/20更完整；但它覆盖的是已记录的这一批候选矩阵，不能补回此前没有完整登记的自适应搜索。将这一轮“未达到预设门”改述为“在该窗口、该比较家族、该成本和区间假设下，增量证据不足”更准确。`38年所需样本`来自当前波动、当前效应和当前阈值的外推，不是市场规律；未拒绝零效应不等于策略不存在，也不能反过来宣称没有胜者已被证明只是分辨率问题。

### 5.3 不再把固定t门当决策器

后续报告同时保留点估计、区间、年度分解、成本敏感性、复杂度和可执行性。不要以`t≥2.5`或“4/6年胜出”机械 KEEP/KILL。一个改善成本和实现复杂度、收益区间不排除小幅损失的方案，可以作为需要前瞻观察的工程候选；一个高t但只在单年/借不到券/不可成交条件下成立的方案不应升级。

区间跨零意味着当前信息兼容多个效应，不是证明等价。若要声称非劣或等价，先基于费用和风险预算定义可接受损失范围，再报告区间与该范围的关系。多seed回答优化随机性及集成稳定性；相同周的多个seed回报不能当作更多市场周。先按已冻结规则形成每周候选与baseline，再在时间维度推断。

## 6. 统一可执行验证协议（拟议，须在下一轮实验前冻结）

### A. 数据、身份及可重复性

固定run ID、父baseline、代码commit、配置diff、数据hash、universe及行业版本、交易日历、时区、所有截止时点、seed、费用、选轮规则及成员数。历史baseline的原产物只读保留，任何会计/契约修复必须同时重放baseline和候选，输出新命名产物；禁止用旧baseline数字对新候选口径。建立候选家族账，记录所有看过的窗口和事后改动，重复命名的同一策略不伪装成新验证。

### B. 时间协议

在历史开发期内部使用预先指定的连续时间训练/验证块，每折训练、缺失填充、缩放、任何特征筛选、epoch选择仅使用当时已成熟标签。先核对完整时间索引，再按真实 `label_end_at` purge。外层年度/阶段回放固定为评估段；一旦外层读数反馈到新方案选择，它就成为下一版的开发数据，日志须标记。未来前瞻按冻结更新日程执行“先预测并封存→等待标签成熟→评估”；如修改规则，建立新版本的观察起点，不回溯替换旧预测。

### C. 低成本筛选与seed确认

先一seed、同算力/同epoch预算筛选少量有明确机制的臂；候选仅在内部验证看收益和风险，历史test不参与挑参数/挑seed。筛选用区间、方向、年度集中度、成本及增量复杂度综合排序，允许“保留观察/证据不足”，不设万能t门。最多进入1–2个候选的3seed确认；所有预定seed都保留，不删“差seed”。同一seed和相同数据顺序可减少比较噪声，但不声称它制造市场独立性。集成方式、seed数和epoch成员规则在读确认结果前固定。

### D. 每个新实验都输出三腿及逐年表

纯多采用冻结多头规则；纯空采用冻结券源过滤、持仓和成本规则；组合采用明确的gross/net exposure与资本分配。模型候选不顺便改变三条执行规则。每个训练臂在其允许读取的验证段就生成以下三腿表；未晋级的臂，其历史test格标“未读取”，不能为了填满表偷读。

| 必备字段 | 说明 |
| --- | --- |
| 身份 | arm、fold/窗口、seed/ensemble、leg、year、完整/部分年度 |
| 时间 | 开始/结束交易时刻、实际天数、预期期间数、已计收益期数、缺口及原因 |
| 收益风险 | 毛/净累计收益、全期年化、Sharpe、MDD、年度净收益、年度Sharpe、年度MDD |
| 执行 | 买/卖双边名义换手、佣金税费、冲击、借券/融资费、持仓数、现金、gross/net exposure |
| 可实现性 | 拒单/涨跌停/停牌次数、延迟退出、券源不足/召回、缺失标记、手数与容量 |
| 增量 | 同期间同腿candidate−baseline周均bps及区间、ΔSharpe、ΔMDD、年度收益差、最差年 |

年度收益给自然年度实际覆盖内的累计回报，2026截至日单列，不用部分年度收益冒充全年。全期年化在日历完整性核实后按实际时间定义；Sharpe清楚说明无风险率、周期和串行相关限制。多、空和组合都看，但预先选择一个主目标与少数风险约束，避免每次在三个腿中挑漂亮指标报告。

### E. 配对块推断及成本敏感性

将同日期的 `(baseline_long, candidate_long, baseline_short, candidate_short, baseline_combo, candidate_combo)` 联合重抽样，保持两臂、三腿的同期相关性。主输出是每期增量净收益的均值bps和95%区间；ΔSharpe必须在每个重抽样中分别重算两个Sharpe再作差，不能把“差值序列的Sharpe”称为“Sharpe之差”。推荐4/8/13周块长作预定敏感性，并说明圆形块拼接和非平稳性的局限；不要择取最有利块长。原始组合净收益序列在现实路径上算MDD，bootstrap重排MDD只作路径敏感性，不声称它给出严格未来最大损失保证。

Ledoit与Wolf讨论了厚尾/时间相关下对两个Sharpe差使用studentized时间序列bootstrap；若本轮只实现百分位块区间，应明确是较简单的描述性实现，不冒充其完整检验。[原始论文](https://www.econ.uzh.ch/apps/workingpapers/wp/iewwp320.pdf)。对多个候选的频率学错误率要求，可在事前完整候选家族上使用联合中心化块重抽样的max统计量或预定Holm等校正；记录未完成家族和适应性新增项目，不把校正当硬升级门。

成本统一展示基准档、两倍交易成本、明确借券费/容量压力档；参数来自可追溯事实或事前情景，不能用最能凸显候选优势的成本档作唯一结论。若改善只来自降低换手，可以称成本效率改善；不能要求它必须是“新alpha”才有价值。

### F. 最终判断卡

对每个候选写一段完整判断：改善哪条腿、效应有多大、区间允许多大损失、是否集中在一个时期/seed、成本和容量是否消耗改善、增加多少参数/运行时/维护面、哪项因果或会计检查尚未通过。状态使用“淘汰（原因）/继续观察/进入前瞻候选”，历史探索性结果不写“已认证实盘alpha”。新前瞻期间即使增加一个周数据也不反复窥探显著性并任意停表；按冻结评审日程累计证据。

## 7. 八小时后续计划与停机条件

这是后续获得实施授权后的资源计划，本次没有启动。历史 `abl2000_base`、s43、s44的8epoch耗时分别837.1、875.0、836.8秒（各自 `training_metrics.csv` 的seconds求和），只可用于粗预算；新分支、当前硬件及并发会改变耗时。第一轮校准若翻倍则缩减候选数，不压缩数据审计。

| 时间预算 | 交付物 | 停机/缩减规则 |
| --- | --- | --- |
| 0–60分钟 | 冻结协议、复现原曲线、标签时点与日历/字段检查、小型会计assert | 不通过则剩余时间先修仪器，不训练新模型 |
| 60–120分钟 | 隔离目录中统一三腿历史基线、修复口径与原口径差异解释 | 尚不能对账则只输出审计，不排名模型 |
| 120–210分钟 | 至多3个单seed、单变化机制候选；相同验证selector | 超时只做2个；不扩大参数网格 |
| 210–330分钟 | 最多1–2个候选的预定额外seed确认；三腿逐年表 | 差seed保留；不以test救活失败臂 |
| 330–420分钟 | 少数预定时间折的两臂回放，或已有分数的配对块/成本分析 | 完整nested计算超预算则明确标“未完成”，不假装六年全验 |
| 420–480分钟 | 效应/区间/年度/成本/复杂度判断卡、封存前瞻规则和未决风险 | 不以最后一小时搜索新winner；允许没有晋级者 |

八小时能够产出可解释的候选与更可靠的评价基础，不能购买八小时之外的独立市场时间。最有价值的结果可能是确认一个实现差异、排除一个机制、或把一个小改善准确地归为需要前瞻观察。
