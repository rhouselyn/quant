## 后续训练的完整状态和恢复操作

新训练每完成一轮，写 training_state.pt，先写同目录临时文件、flush/fsync，再原子替换。它包含模型、AdamW参数组/动量/步数、EMA教师、参数冻结状态、Python/NumPy/Torch CPU/CUDA随机数、增强Generator、已完成轮数、训练指标历史及最佳模型/选轮值。当前训练没有独立学习率调度器或AMP GradScaler；学习率保存在优化器参数组中，分阶段规则仍按绝对轮数执行。将来引入调度器或GradScaler时必须一并保存其状态并扩展恢复测试。

epoch_N.pt、newest.pt 和 best.pt 继续供评分读取，训练恢复只认 training_state.pt。中断最多重做未提交的那一轮；不支持批次中途恢复。恢复时以完整状态为准修复被未完成轮次提前改写的 newest/best/指标和验证分数。原始配置另存 config.initial.yaml；当前配置写 config.yaml。

恢复步骤：

1. 确认旧训练进程已退出，避免同一run被两进程写入。检查 training_state.pt 存在；仅有旧权重时拒绝恢复，不得重置AdamW后冒充续训。
2. 使用该run登记的冻结source和相同环境、设备、数据路径。只允许增加配置epochs，其余配置、实际数组、外部辅助标签、模型包源码及运行时身份必须一致；不匹配立即拒绝。未启动暂缓任务将绑定含完整状态支持的新冻结source，不能使用旧source恢复新run。
3. 从冻结source目录执行原训练命令，末尾加 --resume：`python -u scripts/run_weekly_architecture.py train --root <batch> --dev-data <validation_snapshot> --device cuda --cfg <registered_cfg> --run <existing_run> --resume`。epochs仍为总预算，不是追加轮数。扩预算前把理由和新预算登记，配置改动也要同步任务哈希清单。
4. 不调用旧 continue_training.py 处理v2，它已明确拒绝v2自动测试路径。训练期间仍不计算测试。恢复完成后读取 validation_complete 和 completed_epochs，再单独导出完整验证分数、重新锁定各腿best±1窗口，最后评分测试；扩预算后的结果写新的评分/报告目录，不覆盖旧锁和已发布报告。
5. 队列进程崩溃后仍须核对已完成命令；只恢复失败训练命令并跳过已经发布的评分步骤，不能盲目重放整个多命令job。恢复前核对工作进程和GPU锁；不能仅凭锁文件存在就判断仍在训练。

验收测试 tests/test_training_resume.py 使用真实小模型/AdamW/EMA/dropout/历史增强，比较连续4轮与第2轮中断恢复，以及连续4轮与2轮后扩到4轮。小模型在CPU与本机CUDA上的权重、AdamW、EMA、随机数、各轮权重、验证预测和非计时指标要求完全一致；另测数据/配置漂移、旧权重拒绝、写入失败保留前一完整状态、v2测试隔离、Parquet写入中断恢复及未提交轮数禁止评分。训练与恢复的Parquet输出也原子发布，CSV指标由完整状态修复。

这证明完整状态恢复，不代表所有模型的CUDA运算天然确定。CS/条件摘要的CUDA index_add_包含重复行业索引，当前默认非确定性模式可能产生微小浮点差异，完整状态也无法消除这种内核不确定性。运行时身份记录确定性开关并拒绝变更；本次不改变既有数学实现或强制切换确定性模式。跨硬件、软件版本或这些非确定性内核不承诺位级等价。
