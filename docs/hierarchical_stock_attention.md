# 580股行业与全局信息：架构建议

状态：已切换默认数据集；本文是设计建议，没有实现或训练新注意力模型，不能据此宣称收益改善。

## 数据

- 来源：`data/sw_file_20/` 的600股、31个申万一级行业。
- 移除：综合（51）14股、美容护理（77）6股。
- 保留：其余29个行业的原始20股随机合格样本，580股，不重新抽样。
- 新缓存：`data/sw_580_29x20/weekly.parquet`；股票与行业映射：同目录 `universe.csv`，`industry_id` 按行业代码升序从0编号。
- 日历：2016-09-30～2026-09-11；训练364周，验证78周，测试78个周日期。最后一周没有下一周收益，77个候选收益期中有75期存在有效标签；缺失周沿用原缓存，不补造收益。验证起点2023-09-22，测试起点2025-03-21。
- 默认维持单score头、40周输入、未来5周key、128维embedding、10epochs、Score头尾20%等权、全量RankIC权重0.5。沿用600股配置的编码器分块1000以控制显存；不会把股票池拆成独立损失横截面。
- 行业分类是2026年快照回溯；长期存续筛选有偏差。后续行业模型同样受此限制。

## 当前推荐：行业内与行业间交替，最后追加行业内更新

580股实际相关性分析见 `outputs/industry_580_future_analysis/report.html`，网页入口 `/industry-analysis`。当前首选简化为 `L → G → L → G → L → Score`。

- L：每行业20股+1个行业代表，做self-attention，股票与代表一起更新。
- G：29个行业代表做self-attention，把其他行业的信息写入每个行业代表。
- 最后L：更新后的行业代表将跨行业信息传回股票。这里不需要股票额外cross-attention全部代表。
- 保留个股残差、小幅门控、Pre-LN和FFN。128维，4个注意力头（score仍单头）；每层在29行业间共享权重。

如果G也去掉，只重复L，则没有显式跨行业消息。市场token和股票直接读取全部代表都不是必要条件：市场token提供公共状态摘要或条件变量，cross-attention则绕开单行业代表的信息瓶颈，让每只股票直接选择远端行业。这两项可在简版基线之后独立消融，不作为首版默认。

行业代表以可学习身份向量+当期行业内股票聚合初始化；每次forward只在本日期层间传递，不跨日期保留缓存状态。它无需单独预训练，若预训练也只能用训练期。股票不加任意顺序位置编码。

市场token若只从29代表聚合，不引入新的可观测信息；若加入原始市场收益/波动等，才补充被横截面标准化消除的绝对市场状态。所有股票加同一个score常数不改变排序，市场状态只有通过个股依赖的门控/交互等才可能改变排序。它可能支持状态条件化，也可能增强beta或风格偏好，因此首版先不加。后续试用时仅加少量当期可见变量并限制门控，不把低相关或低损失当作风格风险下降。

29行业之间确有高收益相关，但不能推出必须使用市场token或注意力能预测这些共同涨跌：训练期行业未来1周相关均值0.618，5周累计0.606；首主成分占比约64%/63%。扣除训练期估计的市场成分后，平均绝对行业相关为0.143/0.196，部分行业对仍明显相关。残差市场来自这些行业自身，均值负相关存在机械约束，不能把平均值接近零解释为相互独立。

## embedding与训练损失

推荐以时间编码器未做最终L2归一化的128维输出进入Pre-LN关系模块，关系更新后再归一化并接单score头。保留当前归一化score接口。

InfoNCE不是结构或优化的必要条件。当前实际默认仍为 `Score + InfoNCE + 0.5 RankIC`，本轮分析未修改配置。后续推荐先建立 `Score + 0.5 RankIC` 的简版关系模型基线，再在同结构、数据、epoch/seed和选模标准下比较InfoNCE权重0、0.1、1；没有进行该消融，不能声称关闭将提高收益。

若保留InfoNCE，先作用于关系层之前的个股时间表示，使用独立投影头，避免直接约束行业融合后的表示。当前任务是同一股票40周与未来5周特征窗口的身份匹配，不等于未来5周收益预测；滚动60周特征在两个窗口之间仍大量共享原始历史。训练期当前ret60与未来5周平均ret60的横截面秩相关0.942，vlog为0.890，而ret1仅-0.032。持久指纹可能解释对比任务容易，但不能证明辅助训练必然无效。

此外，本580股缓存60周rolling要求连续有效周，日历空周向后传播缺失：验证期vol60/mom60/volume_z60/range60原值全部缺失；原流程填0再标准化。应先处理或明确屏蔽这类输入问题，再开展正式loss消融；相关诊断没有修改原缓存。

如果InfoNCE全部放在增强后的表示上：不同股票仍作为负例，包含同行股票，与行业公共信息共享存在目标张力；另一方面行业身份又可能使区分跨行业股票过于容易。不能把低对比损失自动解释为更强个股预测。需要监测同业/跨业相似度、行业内RankIC、分数离散度与表示塌缩。

若检验最终表示InfoNCE，必须让未来5周key经过EMA版的完整时间+关系编码器（含行业token、attention和投影头）。当前EMA只有时间编码器，不能直接沿用而让query和key分别对应不同的上下文定义。横截面按同一日期独立计算，不能混入其他日期或未来周；未来key仅用于训练。

## 与现有代码的连接点

- 当前engine在时间编码阶段把 `[日期batch, 股票, 时间, 特征]` 展平成独立股票窗口。时间编码可以继续分块，但之后必须恢复 `[日期batch,580,128]` 再做关系建模，不能在每个chunk内单独做行业/全局SA。
- 当前 `PairRanker.forward` 已经score，需拆出 `encode_temporal` 与 `score_cross_section`，训练、验证、测试推理使用同一路径。
- `dataset_arrays`按symbol排序；行业映射必须按返回的symbols重排，不能假定universe.csv中行业分组顺序与张量一致。
- 注意力的可用性mask只能来自当期及历史行情。当前valid_y表示未来标签是否可得，不能用它作为推理时股票注意力mask。行业padding或不可用股票不得进入pooling或attention；不能因下一周缺失收益而替换候选股票。
- 若关系模块需要输入量纲稳定性，使用LayerNorm；不要把上一轮用于诊断的风格中性化直接接入默认特征流程。

## 方案比较

| 方案 | 优点 | 代价与局限 | 本项目定位 |
| --- | --- | --- | --- |
| 行业均值+市场均值+门控MLP | 稳定、参数少、容易检查信息是否有效 | 池内异质性和关系权重表达弱 | 必做低成本基线 |
| 580股全局SA+行业身份向量 | 能直接学习跨行业个股关系；实现较直接 | 关系自由度更高；容易用行业/市场共性代替个股信号 | 有价值的对照 |
| L→G→L→G→L分层attention | 显式局部与全局信息，匹配29×20结构，保留个股残差 | 代表token形成信息瓶颈；依赖分类质量 | 推荐首个主方案 |
| HIST式概念共享+个股残差 | 针对股票，显式利用已知/隐含概念与个体信息 | 隐含概念挖掘和概念映射带来额外选择，不是简单换层 | 推荐第二阶段备选 |
| MASTER式市场引导时空Transformer | 更广泛建模时序、跨股票关系及市场状态 | 会替换/重构更多时间编码部分，难区分新收益来自哪里 | 暂不整套替换当前系统 |

Set Transformer的可学习诱导点/聚合query、HIST的概念共享与个体信息分解提供成熟的设计参照；本文的29×20分层结构是针对当前数据的组合设计，不是这些论文模型的完整复现。

## 有效比较顺序

在同一580股数据、同一日期切分、同一个股特征预处理、费用、Top20与训练预算下比较：A原单头；B行业/市场均值门控；C行业内/行业间交替并以行业内更新结束；必要时D全局SA或HIST。若加入原始市场侧输入，B/C必须同时获得相同侧输入，并另做一次开关对照，区分收益来自补充信息还是更复杂的聚合。初轮比较固定seed，进一步比较多个seed的验证稳定性；冻结方案后再评估测试。旧500股日历与股票池不同，不能把它的收益直接作为新架构增益。

除全池RankIC和Top20净Sharpe，检查行业内RankIC、行业持仓偏离、市场/波动风格暴露、换手、回撤、关系层前后个股差异。更好获取行业信息不等于更少风格偏好。
