# 研究记录与归档规则

范围：新方案、执行、分析和交接。更新：2026-11-13。返回 [导航](INDEX.md)。本规则对新增记录生效，已有路径按需补链接，不为改名破坏哈希或运行任务。

## 写到哪里

| 内容 | 位置 | 维护方式 |
| --- | --- | --- |
| 阅读入口与当前协议指针 | `docs/INDEX.md` | 只改导航和带日期快照 |
| 跨实验经验 | `docs/research_lessons.md` | 合并同义规则，保留证据来源和适用边界 |
| 可执行方案/预注册 | `docs/research_YYYYMMDD_<topic>_protocol.md` | 执行前冻结；修订写版本、原因、影响范围 |
| 验收结论与解释 | `docs/research_YYYYMMDD_<topic>_results.md` | 进入版本控制；同时记录成功、失败、未完成 |
| 原始输出、日志、状态、权重和机器指标 | `outputs/<batch>/` | 使用既有管道布局；已发布证据不覆盖 |
| 数据与快照 | `data/`或批次快照目录 | manifest标版本、覆盖、来源和哈希 |
| 跨实验判决索引 | `docs/experiment_ledger.md` | 一段摘要+协议/结果链接；更正须引用被替代条目 |
| 可复用实现与检验 | `src/`、`scripts/`、`tests/` | 按现有接口扩展；临时调查代码放批次目录或根目录`tmp_*.py` |

**同步实验树。** 每次登记、完成或更正实验，按[维护说明](experiment_tree.md)在同一次更新中写入[实验树 JSON](experiment_tree.json)。新增实验分配稳定 ID，完成或更正沿用原 ID。同步状态、对照与复用等关系、已核实的效果和证据来源，待验证项记录验证问题。然后在仓库根依次运行 `python scripts/render_experiment_tree.py` 重新生成 HTML、`python scripts/render_experiment_tree.py --check` 核对内容一致性。检查通过后完成归档。

本机私有memory只能缓存仓库文档指针；影响下次研究的经验必须进入仓库。仓库文档可版本化不代表已提交Git，本任务不自动提交或推送。

## 执行前：协议至少写明

- 记录ID、日期/时区、状态（planned/running/complete/failed/deferred/superseded）、父实验、假设及与旧尝试的差异。
- 训练/验证/测试的实际日期、标签成熟规则、推理候选规则、数据快照和预处理拟合范围。
- 基线和参数对照、seed、预算、损失与选轮/融合规则；费用、资本分母、执行假设、主要指标和通过/否决条件。
- 已读过哪些验证/测试；哪些结论只是探索；允许的增量实验和停止条件。
- 实际命令、代码版本或源码哈希、环境、输入路径及哈希、输出目录、任务依赖；恢复方法、资源安排和分项耗时估计。

先确定选轮和实验集合再读测试。用户调整范围时写变更记录并同步实际队列；保存旧任务为deferred/superseded，不能仅改叙述。

## 执行后：结果文档模板

```markdown
# <记录ID与主题>
日期/时区：...
状态：complete / partial / failed / deferred
协议：相对链接；修订：...；父实验：...
代码/环境：commit（如工作区有修改需另给源码哈希）/冻结目录/版本
数据与边界：snapshot、日期、成熟周数、样本覆盖
已读历史：验证/测试的暴露情况

## 结论
支持什么、不支持什么；相对哪个对照；仍缺什么证据。
## 方法与结果
命令、seed与预算、选轮及lock、成本/组合分母、主表、配对区间、压力情景。
## 验收与偏差
要求→实际执行→产物证据；测试命令/结果；失败与未完成项。
## 下一步
依据验证的增量假设、配对对照、预算和队列状态；测试只作描述。
## 证据与复现
相对路径、manifest/哈希、保存位置、恢复或重算命令、限制。
```

正文解释与机器结果分开：表格从产物提取并标单位，读数不能手工改写原CSV来匹配叙述。更正写新版本/目录并说明替代关系；旧原始证据保留。索引指向当前有效版本，旧结果页保留纠正指针。

## 完成与交接清单

1. 核对进程、退出码、queue/state和必需产物一致；partial不能写complete。
2. 发布结果文档并链接协议、输入、机器指标、锁和限制。将可复用教训合并入经验文档；个别模型读数留在结果页。
3. 在台账添加简短判决，在INDEX补任务入口或更新带日期快照；README与AGENTS只链接统一入口，避免重复维护当前状态。
4. 验证新增链接。`outputs/`和`data/`被Git忽略：在版本化结果页保留核心表、证据manifest哈希及复现入口；若需要跨机器复现，记录实际备份位置和校验。未备份则写“仅本机、未归档”，不能把一个本地链接算持久归档。
5. 交接写当前运行/暂缓任务、最后成功产物、下一条可执行命令和阻塞项。没有运行任务也明确写出。结束前列明本轮没有验证的关键条件。
