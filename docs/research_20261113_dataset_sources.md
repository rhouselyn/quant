# A 股历史数据来源与归档规格（2026-11-13）

核查日期：北京时间 2026-11-13。本文为研究与后续实施规格，**不表示行情已经下载、接口已经实测或数据已经通过验收**。本次仅阅读仓库文件、官方网页及 BaoStock 发布包源码；未调用行情/财务数据接口，未安装依赖，未运行模型或回测，未修改现有代码和数据。

建议先建立包括退市证券的历史证券主表，再回填逐证券最早可得的未复权日线及公司行动，最后制作按证据等级区分的训练快照。历史证券全集、供应商当前返回的历史数据、当时真正可见的数据版本，是三个不同对象。

## 2. 来源选择与已核实的接口边界

### 2.1 证券主表必须独立于行情抓取

| 来源和调用规格 | 已核实内容 | 用途与不足 |

| Tushare `stock_basic(list_status='L'/'D'/'P', exchange=...)`，分别请求 | 默认只取 L；输出上市、退市日期及交易所；当前文档另列 G、UN。每次至多 6000 行，2000 积分起、每分钟 50 次 | L/D/P 联合是候选主表；G/UN 保留为预上市信息，不能自动进入交易池。当前状态仍非每日历史状态。[官方说明](https://tushare.pro/document/2?doc_id=25) |

| Tushare `namechange(ts_code=..., start_date=..., end_date=...)` | 提供名称有效起止日、公告日和变更原因 | 辅助曾用名/ST 状态核对，不能仅靠名称字符串认定全部风险警示状态。[官方说明](https://tushare.pro/document/2?doc_id=100) |

历史全集定义为研究期间曾符合证券范围的证券身份并集，而不是今日上市名单。范围应明确为沪、深、北交易所人民币普通股；B 股、ETF、基金、指数、可转债、CDR、新三板其他层级分别标记，不因代码前缀或供应商“全市场”标签自动纳入。北交所挂牌前历史即使被供应商拼在同一序列，也须保留当时市场层级。

全集主表至少保存 `security_id, exchange, security_type, board, list_date, delist_date, historical_codes, source, evidence_uri, coverage_status`。逐年、逐交易所、逐板块对照上市/终止上市名单；首次上市、退市、换码、转板、重新上市与合并都必须能追溯到事件。停牌证券仍属上市全集，只是当日可能不能交易。

### 2.2 行情、复权、分钟数据

| 来源和参数 | 可用范围与限制 | 建议角色 |

上述接口和限制见 [AKShare 行情官方文档](https://akshare.akfamily.xyz/data/stock/stock_quote.html)。文档提供的样例或起始参数不是全证券覆盖保证；本文不把 AKShare 文档中的访问描述当作服务等级协议。

| Tushare 调用规格 | 已核实边界 | 采集约束 |
| --- | --- | --- |
| `daily(ts_code=..., start_date=..., end_date=...)` 或 `daily(trade_date=...)` | 未复权，停牌期间不返回行情；单次 6000 行。文档列最低 120 积分试用、每分钟 50 次；5000 积分档可达每分钟 500 次 | 按证券年度或交易日分片，返回达到上限时继续切分，不能将 6000 行当作全历史完成。[官方说明](https://tushare.pro/document/2?doc_id=27) |
| `adj_factor(ts_code=..., start_date=..., end_date=...)` 或按交易日 | Tushare 自产因子，支持个股全部历史/单日全部股票；2000 积分起 | 与原价、公司行动独立落盘；接口没有声明“任一历史下载时刻的旧因子版本”查询能力。[官方说明](https://tushare.pro/document/2?doc_id=28) |
| `stk_mins(ts_code=..., freq='1min', start_date='YYYY-MM-DD HH:MM:SS', end_date=...)` | 文档明确起始日 **2010-01-01**，支持 1/5/15/30/60min；每次最多 8000 行；需要单独“A股历史分钟”权限 | 这是产品边界，不是每只证券自该日起都有数据的承诺；不能推导出完整逐笔/委托簿。需按时间分片并做实际覆盖验收。[官方说明](https://tushare.pro/document/2?doc_id=370) |

**最早可得日线的口径：** 对每个证券从其上市或研究市场准入日期开始提出回填需求，实际保存 `requested_start, first_returned, earliest_verified, missing_prefix_reason`。本次一手资料核查不足以证明任一免费接口覆盖全部证券、全部上市历史；因此不写统一“从 1990/2000 年完整覆盖”的承诺。若训练只使用 2000 年起，仍可归档更早的可得日线，归档边界与训练边界分别记录。对缺失早期区间进行第二来源核对后，仍未解决的列入缺口账本。

日线、分钟、逐笔成交、逐笔委托、盘口和历史借券库存是不同产品。日线可获取不推导出其他粒度可获取；分钟不提供排队位置、撤单和真实可成交量。新增逐笔或盘口采集前必须单列供应商授权、市场/年份范围、保存和使用权限，不在本阶段承诺无限历史。

## 3. PIT 与版本契约

以下是本项目拟采用的数据契约，而不是声称任一供应商已提供全部能力。

| 证据等级 | 定义 | 允许声称 |
| --- | --- | --- |
| `latest_history` | 今天接口返回的历史值，可能已经更正、复权或补录 | 历史回填；不能声称原始版本 PIT |
| `reconstructed_pit` | 依据原公告正文、公告时间和更正链重建当时公开信息；本地实际采集发生在后来 | 有来源证据的历史时点重建；不声称当时本地/供应商已持有 |
| `observed_vintage` | 具有当时实际采集时间、原始内容及校验和，或供应商可审计 vintage 证明 | 可在相应可见边界内进行严格版本重放 |

每条事件/财务版本至少包含：`security_id, period_end/event_at, published_at, available_at, recorded_at, revision_id, supersedes_revision_id, source_document_id, content_hash, evidence_level`。时间采用带时区表示；`recorded_at` 是本系统实际入库时间，不能伪装成历史公告日。`available_at` 表示在声明的数据接入路径及发布精度下可被研究/决策使用的时间，不能直接复制报告期末。

查询时先冻结数据快照，再按 `available_at <= decision_at` 选择当时可见的版本。严格“本系统当时已知”重放还须满足相应 `recorded_at` 边界；历史重建使用公告证据并明确其等级，不能为了通过该条件篡改采集时间。后来的更正保留为新事件，不能覆盖更正前曾使用的数值。

只有公告日期、没有时分秒时，保守设为该日期之后的下一交易时段可用，记录精度和假设；若原始公告证明更早可见，再按证据修正。实际发布日期缺失时，法定披露截止日只能形成单列的代理实验，不准混入严格 PIT 主结论。若现在下载的是重述后的数值，即使人为滞后 30/60/120 天，也仍不能还原首次公告数值。

历史行业、指数成分、ST、流通股本和融资融券资格同样要保存有效区间及知识时间。今日行业或今日成分名单不能覆盖全部历史。跨表连接必须明确实体身份、报告期/交易日、知识截止日和版本，禁止仅按证券代码做无时间条件连接。

## 4. 复权和退市处理

建议以未复权 OHLC、原始量额、公司行动及其版本为事实层，前/后复权为派生视图。成交价格、限价和持仓股数使用当时原价及真实股数；研究收益的复权算法、现金分红再投资假设单独版本化。

在乘法因子定义成立且已验证时，固定锚点价格可按 `P(t) × F(t) / F(anchor)` 计算；不同供应商的因子定义、现金分红处理可能不同，不能无核对混用。若现金已通过复权收益计入，组合现金账不能再加一次。送转、配股、分红、合并换股分别核对价格跳变、股份和现金账。

`hfq` 不是数据不可修订的保证。十个交易日重叠只检测最近区间，无法发现更早历史被改写；应保留每次内容 hash、差异事件及受影响区间，另对历史年份做轮转核验。发现变更时产生新快照，旧快照仍可复现；不静默全量重写旧实验输入。

退市证券不得从全集、训练样本和持仓账中删除。分别记录最后交易日、终止上市日、转入其他市场日期与可验证清算/换股/现金流；最后价格缺失不能直接当零收益，退市也不能一律假设在最后收盘价卖出。无法核实的退出价值在评估中列未决风险或按预先声明的保守情景处理，不能让失败样本自动消失。

| 2026 年新交易规则 | 沪深新规均于 2026-07-06 生效；沪市公告有暂缓条款。北交所同日施行的新版也有另行通知实施的条文 | 公告日、有效日、暂缓与后续实施日分开；不能把最新正文全条款直接覆盖全历史。[上交所](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)、[深交所](https://www.szse.cn/lawrules/rule/trade/current/t20260424_620190.html)、[北交所](https://www.bse.cn/jygl_list/200028217.html) |
| 主板风险警示涨跌幅 | 上交所 2026 年修订明确由 5% 调整为 10%，生效日 2026-07-06 | “ST 一律 5%”在当前研究截止日已经不成立；其他板块/市场必须分别核对。[上交所修订说明](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20260424_10816474.shtml) |
| 证券交易印花税 | 2023-08-28 起实施减半征收 | 费用表按生效区间，不能用今日成本统一覆盖多年；佣金、最低收费和其他费用按实际合同/当期通知。[官方通知](https://www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20230827_5725662.shtml) |

规则表字段至少为 `exchange, board, security_type, effective_from, effective_to, rule_id, published_at, evidence_uri, suspended_clause`。规则内容覆盖可卖数量/T+1、买卖申报单位和零股、价格最小变动单位、涨跌停、新股/重新上市/退市整理例外、停牌、集合竞价与连续交易、费用和结算。这里提供规则版本需求，不声称已完成 1990—2026 每次制度变化的法律档案。

日线执行只支持带明确假设的估算：触及涨停不意味着可以买入，触及跌停不意味着可以卖出，日内成交量也不是开盘时可用深度。采用实际成交时刻前的可用数据，明确开盘价成交是假设还是有集合竞价/成交证据；无法成交、停牌和不满足最小交易单位时要保留订单拒绝/部分成交状态。需要分钟/盘口才能判断的事项不能由日线伪造。

### 融券数据的关键区别

Tushare `margin_secs(trade_date=..., exchange='SSE'/'SZSE'/'BSE')` 返回每日盘前融资融券标的，包含 ETF；`margin_detail(...)` 返回事后融资融券明细，文档说明存在次日甚至下一周一更新。前者是资格、后者是交易统计，**两者都不是用户可借券库存、费率或锁券确认**。[标的接口](https://tushare.pro/document/2?doc_id=326)、[明细接口](https://tushare.pro/document/2?doc_id=59)

2024-07-11 起暂停的是转融券业务，不应写成全部融券被禁止；同期公告规定自 2024-07-22 起融券保证金比例下限调整。这是已核实的历史事件，未来恢复或进一步变更必须继续版本化核对，不能从这条历史通知推导永久状态。[证监会政策公告（上交所转载）](https://www.sse.com.cn/home/component/news/c/c_20240710_10759727.shtml)

可执行空头至少还需要券商/柜台在下单前提供的 `borrow_available_qty, borrow_rate, term, locate/reservation_status, recall_condition, quote_time`。没有这些记录时，股票多空结果只能称理论排序/对冲研究；实盘候选应改为无券不卖空，或单独研究具有授权及真实可交易数据的对冲工具。不能通过“历史曾有融券余额”反推某日用户借券一定成功。

## 6. 身份、单位和不可变分区方案

内部 `security_id` 一经分配即稳定，不使用“当前六位代码”作为唯一身份。`security_alias` 保存 `security_id, vendor, vendor_symbol, exchange, valid_from, valid_to, available_at, evidence_uri`。北交所旧代码到 920 新代码映射、证券更名与发行人重组分别处理；不同股类不因为同一发行人就合并。旧/新代码跨切换日不能产生两份经济上相同的持仓和行情。

标准化层保留来源代码、原始字段与单位映射；价格统一人民币元、数量统一股、金额统一人民币元、比例明确小数/百分数。单位转换必须逐接口确认，同一供应商的日线和分钟也可能不同；不要凭列名 `vol`、`amount` 推断。异常检查比较同一原价/同一交易时段口径，避免拿复权价与未复权成交额交叉验证。

建议最小落盘结构：

```text
data/ashare_v2/
  raw/<provider>/<dataset>/<request_id>/
    response.<original_format> + request_manifest.json
  silver/<release>/<dataset>/venue=<exchange>/year=<yyyy>/
    part-*.parquet
  snapshots/<snapshot_id>/
    manifest.json + quality_report.json + coverage.parquet + unresolved_gaps.parquet
```

这是未来目录规格，本次未创建上述数据目录。原始响应不可覆盖；规范化文件属于特定快照；只在验收成功后原子发布新的快照引用。按来源/数据集/摄取批次保存 raw，按交易所/年分区 silver，分钟再按月分片；不默认制造“每证券×每日”大量小文件。证券主表、别名、财务版本和公司行动作为独立数据集，不能塞进每日行情宽表后丢失时间语义。

请求清单至少保存接口名、无凭据参数、SDK 版本、请求/完成时间、返回行数、原始内容 hash、错误码、重试次数和单位说明。Token、Cookie、完整认证头不写清单。快照清单保存来源版本、转换代码版本、规则表版本、集合定义、截止时间、PIT 等级和所有文件 hash。

## 7. 后续下载顺序与质量门

以下步骤是后续执行任务，不是已完成记录。第一轮仅做小规模接口验收，覆盖老股、退市、长期停牌、ST、上市初期、除权、新旧代码和每个板块；通过后才扩大回填。

1. **冻结范围和账号权益。** 明确市场、粒度、最早研究日、截止时刻、来源优先级、授权和请求预算。历史日线可尽早回填；分钟/逐笔分开立项。
2. **构建历史主表和别名。** L/D/P、交易所退市名单、历史每日名单及换码公告交叉核对；退市证券请求失败必须保留为缺口，不能删掉后重算覆盖率。
3. **拉日历与原始事实。** 原价、量额、停复牌、涨跌停、公司行动/因子分开下载；按接口上限分片，限制并发、退避重试，权限/字段错误不可无限重试。
4. **拉财务与证据。** 保存每份实际返回版本，关联原公告/更正材料；不能完成原始版本链的证券/期间降级为历史回填。
5. **规范化、对账和隔离。** 对异常响应先隔离，禁止用空结果覆盖已有数据；临时文件校验后再发布，已完成分片以内容与范围核验断点续传。
6. **发布快照。** 生成覆盖矩阵、缺口账本及差异报告；训练和评估只引用已冻结 snapshot ID。

| 质量门 | 必须检查 | 失败动作 |
| --- | --- | --- |
| 身份 | 别名有效区间无歧义；换码不重复；类型与市场可解释 | 隔离冲突，停止相关证券连接 |
| 主键与结构 | 指定来源版本内证券+交易时刻唯一；关键字段类型/时区/单位稳定 | 拒收批次，不静默去重选择未知版本 |
| 生命周期覆盖 | 每证券 first/last、内部缺口；按年/交易所/板块/退市状态报告 | 缺口保留分母；标记未下载/停牌/未上市/退市/源不可得/解析失败 |
| 原价与量额 | 正常有效 bar 为正价格，`low <= open/close <= high`；量额非负；单位与币种一致 | 原响应保留，异常值隔离，不用 clip 隐藏 |
| 交易状态 | 停牌记录、交易日历、涨跌停与原价相容；特殊日例外有证据 | 禁止以假 bar 填充，执行端拒绝假成交 |
| 复权 | 公司行动日与因子变点对应，跨源收益差异可解释；新旧快照差异记录 | 阻断受影响特征/标签，重新派生新快照 |
| 财务 PIT | 报告期、公告时间、可用时间、修订链和证据等级完整；快报/正式报表不混同 | 降级或排除严格 PIT，禁止默认法定截止日补齐 |
| 稳定与权限 | 达到返回上限需切分；空响应含原因；错误码/权限失败可见 | 不能把 success HTTP 或末日到达等同采集完成 |
| 可复现性 | 同一 snapshot 的文件 hash、身份映射和规则版本不变 | 失败则不发布/不启动训练 |

“全部历史归档完成”只在已声明范围内、每个证券及时间片都有数据或明确可审计的缺失结论时成立；若仍有源不可得缺口，应表述为“尽可能完整的归档，附缺口”，不能宣称无幸存者偏差。历史输入完整与当前可交易集合是不同验收项。

首次正式执行的交付物应是数据清单、覆盖报告、退市缺口账本、版本差异、原公告核验样本、成本/请求用量和快照 ID。本文没有这些运行产物，因此不报告下载成功率、实际最早日期或实验收益。

未检查：账号实际权益、服务端行情返回、全部退市覆盖、逐笔授权和完整历史规则档案。主要风险：供应商当前历史值及公告日期字段仍可能不足以还原当时版本，必须保留证据等级与未解决缺口。
